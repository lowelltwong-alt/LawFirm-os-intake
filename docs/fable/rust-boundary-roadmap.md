# Rust Boundary Roadmap

- Status: Fable design output. Aligned with `config/rust-ingestion-transition-policy.json` (candidate/eligible/forbidden scopes) and `docs/rust-ingestion-transition-plan.md`.
- Author: Fable 5, 2026-07-05.
- Doctrine: Rust for deterministic, high-volume, contract-stable leaf tools; Python remains the oracle for anything semantic, evolving, or policy-bearing. Rust **audits before it replaces**.

## 1. Ranked candidate table

Score axes (H/M/L): correctness payoff (does Rust's strictness catch real bugs?), performance payoff, contract stability (will the interface churn?), implementation risk. Rank = judgment over the four, biased to stability.

| Rank | Candidate | Correctness | Perf | Stability | Risk | Verdict |
|---|---|---|---|---|---|---|
| 1 | Fixture boundary + prohibited-write + custody scanner (synthetic-name namespace regexes, `contains_real_*` flags, path allowlists, §6 shingle audit from L&E roadmap) | H (a missed custody violation is the worst repo failure) | M | H (contracts are the boundary rules themselves — already versioned files) | L | **build first — audit mode** |
| 2 | Source inventory + sha256 hashing + duplicate detection | M (Python is fine, but byte-exactness across OS/encodings is where Python drifts) | H on big bundles | H (`eligible_hot_path_scope` already lists it) | L | build second |
| 3 | Bulk JSON/schema validation of run artifacts + manifest validation (`ARTIFACT_MANIFEST`, contracts.lock) | M | H (validation-runtime 3600s policy pressure) | M (schemas still evolve — pin to exported JSON Schema, regenerate bindings) | M | third; validate against exported schemas, never hand-model |
| 4 | Offset-preserving segmentation + segment evidence-ref emission | H (offset bugs silently corrupt every downstream evidence ref) | H | M (segmentation rules still move) | M | audit-mode only until segmentation contract freezes |
| 5 | Matter-link **key normalization** primitives (string algebra of §3 feature matrix: claim-number canonicalization, entity suffix stripping) | M | M | L today (ML PRs land first) | M | defer until PR-ML2 stabilizes; then port normalizers only, never the rules |
| 6 | Document-label offset indexing / CourtListener snapshot normalization | M | M | M | M | opportunistic, after 2 |

Note the deliberate inversion: the transition policy's `candidate_rust_hot_path_scope` leads with ingestion; this roadmap puts **custody/boundary scanning first** because its correctness payoff is governance-critical, its contract is the most stable, and it is pure leaf (read files → report). It is also the least tempting to grow semantics into.

## 2. First Rust PR (Codex slice)

**PR-RS1 — `intake-custody-audit` (Rust, audit-only binary)**
- Purpose: single static binary that scans a repo tree or run dir and reports: prohibited-write patterns, real-data flag violations (`contains_real_*`), non-synthetic namespace leaks (emails/domains outside `*.example`/allowlist), path-boundary violations for fixtures, and (phase 2) the ≥8-token shingle overlap audit against declared public snapshots.
- Layout: new top-level `rust/custody-audit/` (cargo workspace), CI job builds + runs it in **audit mode alongside** the existing Python guards; divergence = CI failure of the *audit*, not the build.
- Contract: reads `config/data_policy.yaml` + a new `config/custody-audit-rules.yaml` (shared by Python and Rust — one rule source, two engines); emits `custody_audit_report.json` matching a JSON Schema exported from a small Python reference model.
- Tests: Rust unit tests + a **parity pytest** that runs both engines over `examples/` and asserts identical findings sets.
- Validate: `cargo test`, `cargo clippy -- -D warnings`, `PYTHONPATH=src pytest tests/test_custody_parity.py`, full suite.
- Risk: low. What NOT to do: no fixing/rewriting files, no network, no YAML-driven code execution, no fuzzy matching, no expansion into classification of *what* the data means.

## 3. Python/Rust parity strategy

- **One rule source.** Any behavior both engines implement must be driven by a shared, versioned config file; divergence in code is allowed, divergence in rules is not.
- **Golden parity corpus.** Every ported function gets a `parity/` fixture dir: inputs + expected canonical JSON output, generated by the Python oracle, reviewed once, then frozen. Rust must match byte-for-byte after canonical JSON serialization (sorted keys, fixed float formatting — define the canonical form once; floats in custody/inventory land are avoided entirely, currency stays Python-side).
- **Permutation/encoding hostile set.** Parity fixtures must include: UTF-8 with BOM, CRLF/LF mixes, NFC/NFD Unicode party names, >2MB single documents, zero-byte files — the places Python and Rust actually diverge.
- **Property tests both sides.** Same invariants (e.g. "every reported offset round-trips to the same byte slice") as Hypothesis (Python) and proptest (Rust).
- **CI parity gate.** Parity failures block; the failing side is not assumed — a human decides which engine is right, and the decision becomes a new frozen fixture.

## 4. Replace vs audit decision rule

A Rust tool may **replace** its Python counterpart only when all hold: (1) ≥4 weeks of green parity in CI including at least one real divergence caught and adjudicated; (2) the interface contract is in `contracts.lock.json` (or equivalent) and unchanged over that window; (3) the Python implementation remains in-tree as the oracle for parity fixtures (deprecated, not deleted); (4) `required_rust_transition_gates` in `config/rust-ingestion-transition-policy.json` are checked off in a DECISION_TRACE. Until then, Rust runs in audit mode: compute, compare, report, never authoritative.

Semantic layers (budget policy, legal taxonomy, matter-link *rules*, learning) stay Python indefinitely: they change with human review cadence, and rewrite cost would freeze exactly the layers that must stay soft.

## 5. Codex handoff order

1. **PR-RS1** custody-audit binary (above) — after PR-EX1 lands (so violations emit taxonomy-conformant exception candidates via the Python wrapper).
2. **PR-RS2** source inventory + sha256 + duplicate detection in audit mode, parity corpus included (hostile encoding set mandatory).
3. **PR-RS3** artifact JSON Schema bulk validator (uses exported schemas; wire into validation runtime within the 3600s policy).
4. **PR-RS4** segmentation offset auditor (audit-only; replacement decision deferred).
5. Reassess after ML2: port matter-link normalizers per rank 5.
