- Status: Fable design output, candidate-only. Second pass; turns `docs/fable/rust-boundary-roadmap.md` §3–4 into an exact promotion ladder with gates, artifacts, and the next two tool picks.
- Author: Fable 5, 2026-07-05.
- Alignment: `config/rust-ingestion-transition-policy.json` (its `required_rust_transition_gates` map onto ladder stages below; its `forbidden_rust_scope` is restated verbatim as the never-own list).

## 1. The promotion ladder

Five stages per tool. A tool's stage is recorded in a new `config/rust-tool-ladder.json` (one entry per tool, append-only history), so "where is tool X on the ladder" is a config fact, not tribal memory.

```
S0 candidate      → design accepted in rust roadmap; no code
S1 shadow         → Rust builds in CI, runs on parity corpus only; failures informational
S2 audit          → Rust runs on every real CI invocation alongside Python;
                    divergence FAILS CI as an audit finding; Python remains authoritative
S3 co-sign        → both engines run; outputs must be identical; EITHER failure blocks;
                    Rust output is the one consumed downstream, Python recomputes and verifies
S4 authoritative  → Rust is the engine; Python retained in-tree as parity-fixture
                    generator + fallback, exercised weekly by a scheduled parity job
```

### Gate criteria (to move up one stage)

| Transition | Gates (all required) |
|---|---|
| S0→S1 | parity corpus exists (§3) with reviewed goldens; canonical JSON serialization defined; cargo clippy/test green |
| S1→S2 | 2 weeks green shadow; hostile set (§4) fully represented; rule-source config shared (one rules file, two engines) |
| S2→S3 | ≥4 weeks green audit; **≥1 real divergence caught and adjudicated (§5)** — if none occurred naturally, one is injected deliberately (a seeded mutation in a fixture) to prove the pipeline detects and routes it; interface pinned in `contracts.lock.json` |
| S3→S4 | ≥4 weeks green co-sign; DECISION_TRACE recorded mapping every `required_rust_transition_gates` item to evidence; human sign-off recorded in the ladder file |
| any → down | any unexplained divergence at S3/S4 demotes the tool one stage automatically (ladder entry appended); this is the safety valve that keeps S4 honest |

The deliberate-divergence injection at S2→S3 is the ladder's key trick: a gate that requires an event which might never happen naturally invites gate-rotting; injecting one converts "wait and hope" into a testable drill.

## 2. Next two Rust tools (after custody/boundary audit, PR-RS1)

Per the ranked table in the rust roadmap, and unchanged by re-review:

1. **`intake-source-inventory` (RS2): source inventory + sha256 + duplicate detection.** Rationale: already in `eligible_hot_path_scope`; byte-exactness across encodings is where Python actually drifts (BOM incident, below); contract is the most stable non-governance surface (`source_ids`, `source_hashes`, read/availability states, coverage summary — all in `required_parity_dimensions` already).
2. **`intake-artifact-validator` (RS3): bulk JSON Schema validation of run artifacts + manifest checks.** Rationale: validation-runtime pressure (3600s policy) gives a real performance payoff; schemas are exported machine artifacts, so the Rust side binds to generated schema files, never hand-modeled types — schema churn costs regeneration, not rewrites.

Both start at S1. Segmentation/offset tooling stays audit-capped (S2 max) until segmentation contracts freeze, per the roadmap.

## 3. Parity corpus

- Location: `parity/<tool>/cases/<case>/input...` + `expected.json`; goldens generated by the Python oracle, human-reviewed once, then **frozen** (changes require a new case or an adjudication record, never regeneration-in-place).
- Canonical output form (defined once, both engines): UTF-8, LF, sorted keys, no insignificant whitespace, integers where possible, floats forbidden in leaf-tool outputs (hashes, counts, offsets, byte lengths only — currency and hours never flow through leaf tools).
- Coverage floor per tool: every branch of the Python implementation hit by ≥1 case (measured with coverage on the oracle when generating).
- Property tests both sides (Hypothesis / proptest) sharing the same invariant statements, e.g. inventory: "every reported (offset, length) slices the original bytes to the hashed content"; validator: "verdict is invariant under key reordering of the input JSON".

## 4. Hostile encoding / large-file test set (mandatory before S2)

| Case family | Contents |
|---|---|
| BOM | UTF-8 with BOM at file start; BOM mid-stream (concatenated files); UTF-16 LE/BE with BOM (must be *rejected identically*, not decoded) |
| Normalization | NFC vs NFD party names (é as one vs two codepoints); identical visual strings, different bytes — hashes must differ and both engines must agree they differ |
| Line endings | CRLF, LF, lone CR, mixed within one file |
| Degenerate | zero-byte file; whitespace-only; single byte; file with only a BOM |
| Scale | >2MB single document; 10k tiny files (inventory); deeply nested JSON at the validator's declared depth limit (limit must be explicit and equal in both engines) |
| Invalid | overlong UTF-8 sequences, lone surrogates, truncated multibyte tails — both engines must reject with the same case verdict |

Live motivation, recorded as evidence: this repo's own `.digital-asset/mail/outbox.jsonl` begins with a UTF-8 BOM, and a naive `utf-8` JSON read of it failed during the 2026-07-05 DAD-mail run until `utf-8-sig` was used. Encoding divergence occurred *inside the governance mailbox itself* — the hostile set is not theoretical.

## 5. Divergence adjudication protocol

1. CI divergence produces a `parity_divergence_report.json`: tool, case (or live input hash), both outputs, first differing path, engine versions.
2. A human adjudicates **which engine is right** (never assume Python; never assume Rust). The decision is recorded as `parity/<tool>/adjudications/<id>.json`: verdict (`python_correct | rust_correct | both_wrong | spec_ambiguous`), rationale (observable), fix PR ref.
3. Every adjudication yields a **new frozen fixture** reproducing the divergence — the corpus grows only through adjudication and coverage gaps.
4. `spec_ambiguous` verdicts are the valuable ones: they force a rule-source config clarification (one rules file, two engines) and count toward the S2→S3 gate.
5. Exception candidate emitted per divergence (`issue_family: rust_parity_divergence`, Lake class `workflow_escalation`); clustered adjudications with the same first-differing-path become one DAD lesson.

## 6. What Rust must never own

Verbatim from `config/rust-ingestion-transition-policy.json#forbidden_rust_scope`, restated as ladder law — no tool containing any of these ever enters the ladder: legal classification; party-role assignment; matter routing; conflict clearance; budget decisioning; dataset selection/training decisions; public-record download or purchase; budget learning promotion; legal training-corpus admission; human confirmation; exception-lake persistence; connector/external writes; canonical authority changes. Additionally (Fable): matter-link *rules* (only key normalizers may ever be ported, and only post-ML2 stability), and anything consuming an LLM output.

## 7. Codex handoff

1. **PR-RSL1 (low):** `config/rust-tool-ladder.json` (schema: tool_id, stage, history[], gate_evidence{}), a `rust-ladder` CLI check that CI runs (asserts declared stage matches CI wiring — e.g. an S2 tool must have its audit job present), custody-audit tool (RS1) registered at its current stage.
2. **PR-RS2 (medium):** `rust/source-inventory/` at S1: crate, parity corpus incl. full hostile set, shared canonical-JSON writer crate (`rust/parity-core/`), Python-side `tests/test_parity_source_inventory.py`.
3. **PR-RS3 (medium):** `rust/artifact-validator/` at S1 binding to exported schemas; declared depth/size limits mirrored in a shared config.
4. **PR-RSL2 (low):** divergence machinery — report format, adjudication file schema, injected-divergence drill script, exception-candidate emission (`rust_parity_divergence` family; depends on PR-EX2).

**Must not do:** skip S1 for "trivial" tools; regenerate frozen goldens in place; let a tool sit at S2 indefinitely without ladder-file review dates (each entry carries `review_by`); port anything on the never-own list; treat green parity as proof of *value* (it proves equivalence only — retiring a tool is still allowed).
